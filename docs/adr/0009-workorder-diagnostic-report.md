# ADR 0009 — İş Emri Diagnostik Raporu (apps/api → diag-service İstemcisi)

**Karar:** Yeni, tenant-scoped bir `WorkOrderDiagnosticReport` modeli eklendi: `tenantId, workOrderId, reportType (enum DTC|WOT), fileName, result (Json), uploadedBy, createdAt`. `apps/api` artık `apps/diag-service`'in `POST /dtc/parse` ve `POST /wot/analyze` uçlarını çağıran bir istemciye (`src/diagService/diagServiceClient.ts`) sahip — akış: kullanıcı bir log dosyası yükler → apps/api dosyayı diag-service'e multipart olarak iletir → yanıt zod ile doğrulanıp `result` alanına ham JSON olarak yazılır.
**Gerekçe:** DTC (`matches`/`unknown_codes`) ve WOT (`row_count`/`findings`) yanıt şekilleri kökten farklı; bu erken aşamada ikisi için ayrı normalize tablolar açmak (ör. ayrı `DtcMatch`/`Finding` satır tabloları) gereksiz karmaşıklık — `Json` kolonu, diag-service'in KENDİ sözleşmesiyle (bkz. `packages/shared/openapi/diag-service.json`, zod ile doğrulanmış) zaten tutarlılığı garanti edilmiş veriyi kaybetmeden taşıyor.
**Kısıt:** diag-service'e erişilemezse (bağlantı hatası/30sn timeout) `DiagServiceUnavailableError` → HTTP 503 — **kuyruğa alma/retry YOK**, kullanıcı net bir hatayla bilgilendirilir ve isterse tekrar dener. diag-service 400/422 döndürürse (bozuk dosya) → 400. Yanıt 200 ama zod doğrulamasından geçmezse (sözleşme drift'i — `test_openapi_contract.py`'nin YAKALAYAMADIĞI çalışma zamanı sürprizi, ör. iki servis farklı commit'lerde) → 502.
**Kısıt:** `packages/shared`'e `openapi-typescript` ile üretilen tipler (`src/generated/diagServiceTypes.ts`) eklendi — Prisma client'ın `apps/api/src/generated/prisma`'sıyla AYNI konvansiyon: gitignore'lu, `npm run generate:diag-types` ile yeniden üretilir, commit edilmez. Çalışma zamanı doğrulaması için AYRICA elle yazılmış zod şemaları (`src/schemas/diagServiceContract.ts`) var — ikisi de aynı OpenAPI sözleşmesini yansıtıyor, sözleşme değişirse ikisi de elle senkronize edilmeli (otomatik senkron testi bu turda kapsam dışı).
**Durum:** Kod yazıldı, fetch mock'lanarak (başarılı/503/400/502 senaryoları dahil) test edildi. Gerçek diag-service + gerçek Postgres'e karşı uçtan uca doğrulama bu oturumda yapılamadı (bkz. `docs/local-postgres-setup.md`) — ortam kurulunca doğrulanacak.
