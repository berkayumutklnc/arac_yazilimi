# ADR 0003 — WorkOrder Durum Makinesi ve Audit Log

**Karar:** `WorkOrderStatus` enum'ı `DRAFT, ACCEPTED, IN_PROGRESS, AWAITING_PARTS, QUALITY_CHECK, DELIVERED, CLOSED, CANCELLED` (eski `OPEN/AWAITING_AITM` kaldırıldı, `CANCELLED` bu revizyonda geri eklendi). Ana zincir hâlâ **sıkı doğrusal**, ama artık iki bilinçli dal var: `QUALITY_CHECK → IN_PROGRESS` (rework — kalite kontrolde başarısız olan iş tekrar üretime döner) ve `DRAFT/ACCEPTED/IN_PROGRESS/AWAITING_PARTS → CANCELLED` (iptal). `DELIVERED`/`CLOSED`'dan iptal YOK — teslim edilmiş/kapanmış bir iş emri geri alınamaz. Bu iki dal için `reason` **zorunlu**; zincirdeki normal geçişlerde opsiyonel/yok.
**Gerekçe:** İlk sürümde rework/iptal "bu görevde talep edilmedi, ileride ayrı bir görev olarak eklenebilir" denilerek kapsam dışı bırakılmıştı (aşağıya bkz.) — bu revizyon tam olarak o ertelenen genişletmeyi kapatıyor. `reason` zorunluluğu yalnızca bu iki "normal olmayan" dala uygulanıyor çünkü ikisi de iş emrinin geçmişinde bir açıklama gerektiren istisnai olaylar (neden rework, neden iptal); düz ileri akışta zaten durumun kendisi yeterli bağlam.
**Yeni model / genişletme:** `WorkOrderStatusAuditLog`'a `reason String?` eklendi — normal geçişlerde `null`, rework/iptalde dolu. Kolon adı ve semantiği (tenantId, workOrderId, fromStatus, toStatus, changedBy, changedAt) değişmedi.
**Kısıt:** Geçersiz geçiş denemesi hâlâ `InvalidWorkOrderTransitionError` → HTTP 409; iş emri bulunamazsa `WorkOrderNotFoundError` → HTTP 404. Yeni: rework/iptal `reason` olmadan denenirse `MissingTransitionReasonError` → HTTP 400 — update/audit log yazılmadan reddedilir (geçersiz geçişle aynı "yan etkisiz reddetme" garantisi).
**Durum:** Şema/makine/servis/route güncellendi, Vitest + Fastify `inject()` ile doğrulandı. Gerçek Postgres'e karşı henüz doğrulanmadı (bkz. `docs/local-postgres-setup.md`) — ilk `prisma migrate dev` bu alanları da kapsayacak.
